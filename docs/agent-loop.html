agent = LLM + tools + a loop
Part 1 · demo_single.py

One agent: think, act, observe, repeat

The model never runs anything. It asks for a tool, your code runs it, and the result is added to the conversation. The messages list on the right is the agent's entire memory. Watch it grow.

messages[] · what the model sees next call
    Part 2 · demo_multi.py

    Many agents: an orchestrator with specialist workers

    Each worker is a whole agent wrapped as a tool (as_tool()). It gets its own prompt, its own tools and a fresh, empty context. Only its final answer travels back up. The workers share work through files in the workspace, not through memory.

  Part 3 · agentic/llm.py
  
    Swapping the model only changes the adapter
    
  
    The loop in agent.py keeps messages in one neutral shape. Each backend class translates that shape to its provider's API and back. Choose one with a flag.
    
  
    agent.py loop ⟷ llm.respond(system, messages, tools)
    
  
    
    
    MockLLM
    no flag · offline
      
    • Replays a scripted list of replies
    • Tools still run for real
    • Good for learning and for tests
    
    
    GeminiLLM
    --gemini · gemini-3.5-flash-lite
      
    • tool_use ⟶ function_call part
    • tool_result ⟶ function_response part
    • assistant ⟶ role model
    • Sends the original part back so its thought_signature is kept
    
    
    ClaudeLLM
    --live · claude-opus-5
      
    • Neutral shape is Claude's native one, so it needs no translation
    • Content blocks go straight back into messages
    
  
    

    



    
  Choosing a design
  
    Workflow, agent, or several agents?
    
  
    
    
    
      
    DesignWho decides the next stepUse it whenCost
    
      
        
    WorkflowYour code, in a fixed orderThe steps are known ahead of time (draft → review → fix)Lowest and predictable
    
        
    Single agentThe model, one turn at a timeThe path depends on what it finds along the wayGrows with the number of turns
    
        
    Orchestrator + workersA lead model delegates to specialistsThe work splits into parts that need different roles, tools, or a clean context, or can run in parallelHighest; each worker is a full agent run
